Agents that keep working where the internet doesn't reach.

LatentMesh Air moves meaning between AI agents over LoRa, ham radio, Bluetooth, WiFi — even plain audio. No cloud. No cell towers. Runs on a $10 microcontroller.

Your agents stop at the edge of coverage

A sensor fleet on a farm. A survey team in a canyon. A boat forty miles out. Equipment in a warehouse with no WiFi. The moment there's no signal, anything cloud-dependent simply stops.

That's a hard limit on where autonomous systems can go — and most of the planet is on the wrong side of it.

LatentMesh lets them talk to each other instead

Give each node a cheap radio and they form their own mesh. Messages hop node to node, routing around whatever's in the way. No tower, no subscription, no backhaul.

Range depends on the radio you pick — LoRa commonly covers 2–15 km line of sight, and each hop extends that further.

The catch: these links are tiny

A long-range LoRa link gives you a few hundred bytes per message and strict limits on how often you may transmit. Sending raw JSON conversation history is hopeless — one message blows your whole budget.

So LatentMesh sends a bounded semantic envelope instead: what changed, how important it is, which facts must arrive exactly, and a hash so the receiver can tell if its picture has drifted.

Nodes drop out. That's expected, not an error.

Radios lose line of sight. Vehicles drive behind hills. Batteries sleep to save power.

Messages queue and forward when the node returns, with replay protection so a repeated frame can't be reprocessed as if it were new. You design for intermittence instead of fighting it.

One envelope, whatever radio you have

The same message travels over LoRa packets, ham HF/VHF, Bluetooth, WiFi UDP — or as audio tones through any voice channel, including a handheld radio held up to a speaker.

Swap the carrier without touching your agent code. Everything above the transport stays identical.

When one node finds signal, everyone benefits

Put a gateway anywhere in the mesh that has connectivity — a vehicle that drives back into range, a hilltop repeater, a base station — and it bridges the whole mesh to online services.

The bridge decodes and republishes at a single, explicit boundary. Radio bytes never tunnel blindly onto the internet.

getting started

Run it in about five minutes

Everything below runs on a laptop with no radio hardware at all — the transport is simulated so you can build and test the whole path before buying anything.

  1. Clone and run the test suite

    Confirms the whole stack builds on your machine.

# Rust workspace — core, radio, Meshtastic adapter, bridge
git clone https://github.com/ruvnet/LatentMesh
cd LatentMesh
cargo test --workspace

  1. Build the portable C core

    The same framing and error correction, allocation-free, for microcontrollers and embedded targets. Sanitizers on by default here.

cmake -S c -B /tmp/lm-air -DLM_AIR_ENABLE_SANITIZERS=ON
cmake --build /tmp/lm-air
ctest --test-dir /tmp/lm-air --output-on-failure

  1. Check the ESP32 logic on your host

    The microcontroller firmware's decision logic, testable without flashing a board.

make -C firmware/esp32/host_tests test

Sending your first message

The Meshtastic adapter takes your payload, fragments it to fit the radio, and hands you frames ready to write to the device over serial or TCP.

use latentmesh_meshtastic::{MeshtasticAdapter, OutgoingMessage};

let mut radio = MeshtasticAdapter::new()?;
radio.set_destination(/* node id */ 0xffffffff);

// One call → the frames your radio should transmit
let frames = radio.encode_message(OutgoingMessage { .. })?;

// Feed bytes back in as they arrive; you get a whole
// message once every fragment has landed.
if let Some(msg) = radio.ingest_from_radio(&bytes)? {
    // reassembled and verified — use it
}

Reassembly, ordering, duplicate rejection and replay defence are handled for you. A message can span up to 32 fragments.

hardware

What you actually need

Nothing, to start. When you're ready to go over the air, the cheapest useful setup is two LoRa boards.

Nothing at allSimulated transport. Build and test the full path on a laptop.
2 × LoRa boardsAny Meshtastic-supported board. Roughly $25–40 each, antenna included.
ESP32-S3Runs the firmware directly — WiFi UDP, BLE, KISS UART, I²S audio.
A handheld radioLicensed operators: audio tones through the speaker/mic path of gear you already own.

RF licensing, power limits and band rules are yours to comply with. LatentMesh handles the bytes above the transceiver and deliberately owns nothing that touches transmit legality.

Safety properties you get by default

Fail closed

A frame that fails its checksum, signature, replay window or reassembly is dropped. Nothing downstream can wave it through.

Bounded everything

Frame sizes, fragment counts and queues are all capped. A malformed or hostile transmission can't exhaust memory.

Exact where it matters

Critical values are carried deterministically. Compression never applies to the facts you marked as must-arrive-intact.
