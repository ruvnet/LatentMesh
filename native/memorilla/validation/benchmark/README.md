# Native memory benchmark

Two measured rounds on Apple M4 Pro, 48 GiB RAM, Node 22.22.1 and Rust 1.97.1. Each version has 200 timed reads per case, with 20 warmup reads before each round. F32 throughout. The released Stage 3 memory checkpoint uses 2560 input dimensions, 16 memory slots, 4096 output dimensions and two cross attention layers.

CPU batch throughput is about 260 queries/s for 128 documents and 228 queries/s for 1024 documents. Metal reaches about 458 queries/s for the 1024 document batch. Latencies include napi worker dispatch, validation, hashing and the host output copy. They exclude document encoding, decoder generation and network transfer. All inputs are seeded synthetic normalized embeddings, so these are numerical and performance results, not task accuracy measurements.

Single query Metal latency did not consistently improve: the 1024 document case regressed by about 5% in the pooled samples. Host load, clock rate and thermal state were not controlled. Use the raw observations and repeated trials when sizing deployments; do not extrapolate these Mac measurements to Linux or CUDA.

## Changes measured

The portable algorithm change removes question Q/K projections and repeated slot output projections because attention over one question key has softmax weight one. It saves 209,715,200 dense multiply accumulates per query at dimension 2560. Materializing only the retained value projection releases 52,449,280 bytes of unused F32 query Q/K weights.

Shared collection batches pack queries into the attention row dimension. Every softmax row still attends to the same document keys. This avoids broadcasting document K/V across the query batch. A 1024 document cache occupies 40 MiB independently of batch size. A 9 query masked fixture additionally checks that packed and individual reads agree.

The macOS release enables Candle Apple Accelerate for CPU matrix multiplication. The portable algorithm alone is recorded in algorithm-only-cpu.json and algorithm-only-metal.json. Linux keeps the portable CPU implementation; no Linux performance gain is claimed from Accelerate.

The maximum difference from the original binary across both release rounds was 0.00007248 on CPU and 0.00002313 on Metal. The acceptance threshold is 0.0003. Independent upstream PyTorch checkpoint checks use a tighter 0.0002 bound. F16, BF16, CUDA and full pretrained encoder/decoder task quality require separate qualification.

## Reproduce

The harness is node/scripts/benchmark.cjs. Use a clean build of each source commit and preserve each binary before rebuilding. Download the memory config and memory.pt from memorilla/Memorilla-Qwen3-8B revision f6b15af56aa687861c8d2d03b1cd8f7979881361. The checkpoint hash in every receipt is edad84f1ee5b3896ecb51fd0391187d5d3c39b21bd1dc06ae3943ac5618fbb0a.

Baseline build: e0ddc288894ea8207eaf33c6f9d13f2770b89315 with features metal. Release build: 2cf14fc93d230f9d1b4b031fe85977f2bd1221fd with features metal,accelerate. Binary hashes are recorded in each receipt. The sourceCommit field in raw receipts names the harness checkout, not necessarily the saved baseline binary; comparison.json supplies explicit build provenance.

```sh
cd native/memorilla/node
npm ci
npm run build -- --features metal,accelerate
node scripts/benchmark.cjs /models/memorilla/stage3 ./memorilla.darwin-arm64.node cpu ../artifacts/current-cpu.json /path/to/baseline-cpu.json
node scripts/benchmark.cjs /models/memorilla/stage3 ./memorilla.darwin-arm64.node metal ../artifacts/current-metal.json /path/to/baseline-metal.json
```

Omit the final baseline argument on the first run. Keep the adjacent .bin files generated by that run: the comparison checks every returned output element. Run one backend and process at a time on an otherwise idle machine. The receipt includes all 100 raw latency samples, load/write observations, process peak RSS, machine metadata and binary SHA256. Write timing is a single cold observation and is not a stable percentile.

Acceptance test: both CPU and Metal benchmark comparisons must pass the 0.0003 numerical bound; run the independent checkpoint check and native behavioral tests before publication. Deployment task quality must additionally compare the exact model pair with ordinary RAG and shuffled memory.
