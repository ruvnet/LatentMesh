**Native Memorilla for LatentMesh**

Rust inference and asynchronous napi bindings for the Stanford Memorilla memory model. The inference path is entirely native: local checkpoint loading, Qwen3 text embedding, question conditioned memory, cached document attention, input embedding delivery, and greedy decoding. Python is used only to generate independent test fixtures.

This is a separate Cargo workspace because LatentMesh's root workspace pins half 2.4.1 for Rust 1.77, while Candle needs a newer half. The existing transport and authority policy are unchanged. Integration uses LatentFrame JSON with an explicit ObserveOnly authority; it never promotes an edge.

**Build and run**

Rust 1.88 or newer and Node 20.17 or newer are required. This checkout was tested with Rust 1.97.1 and Node 22.22.1 and 26.4.0 on Apple Silicon. The default build uses CPU. Metal and CUDA are optional Cargo features and never selected implicitly.

```sh
cd native/memorilla
cargo test --locked -p latentmesh-memorilla
cd node
npm ci
npm run build
npm test
node examples/embeddings.cjs
```

For Apple GPU support and accelerated CPU matrix multiplication, build with `npm run build -- --features metal,accelerate` and pass `metal` as the device. For a configured CUDA toolchain, build with `npm run build -- --features cuda` and pass `cuda`. CUDA has not been executed in this validation. A requested backend absent from the binary fails explicitly.

**Node interface**

```js
const { loadMemory, exportFrame } = require('@latentmesh/memorilla')

const memory = await loadMemory(
  '/models/memorilla/stage3',
  'tenant:acme',
  1024 * 1024 * 1024,
  'cpu',
  'f32'
)

// Float32Array of N * 2560 values from the checkpoint's Qwen3 embedding model.
await memory.write('history:v1', documentEmbeddings)
// One or more contiguous 2560 dimensional question vectors.
const tokens = await memory.read('history:v1', questionEmbeddings)
// tokens.shape is [batch, 16, 4096] for released checkpoints.
const packet = JSON.parse(exportFrame(tokens, 'Qwen/Qwen3-8B@PINNED_REVISION', 1, 0))
// packet.frame parses as latentmesh_core::LatentFrame, at ObserveOnly.
await memory.delete('history:v1')
```

Release archives are published with the repository under the `@latentmesh/memorilla` package name. Install the archive with `npm install /path/to/latentmesh-memorilla-0.1.0.tgz`, or use the generated local `node/index.js`. Registry publication is separate from GitHub asset publication. TypeScript declarations are generated by napi during the build and include the concrete Promise return types.

Calls to load, write, read, delete, stats and answer execute on native workers. Input typed arrays are copied while JavaScript owns the call, before scheduling. Output Float32Arrays own their data. One handle serializes its operations; callers must await a write before a dependent read. Separate handles isolate collections even if IDs match. The scope string is a namespace, not authentication: the application must authorize callers before handing them a handle.

The budget limits resident collection cache bytes and each read's estimated attention workspace separately. It does not cap model weights, input copies, or the combined peak during an atomic collection replacement. Oversized writes preserve the prior collection. Oversized query batches fail before attention allocation. Deletion removes the live collection; persistent source documents and deletion policy belong to the application.

**Native text pipeline**

```js
const { loadAgent } = require('./index.js')
const agent = await loadAgent(
  '/models/memorilla/stage3',
  '/models/Qwen3-Embedding-4B',
  '/models/Qwen3-8B',
  'tenant:acme',
  1024 * 1024 * 1024,
  'metal',
  'f32'
)
await agent.write('history:v1', ['The deployment window is Tuesday at 10:00.'])
const answer = await agent.answer(
  'history:v1', 'When is the deployment window?',
  'Answer using the supplied memory.', 64
)
console.log(answer)
await agent.delete('history:v1')
```

All model directories are local. This library makes no network calls and runs no subprocesses. Memory directories contain `config.json` and either `memory.pt` or `memory.safetensors`. The native PyTorch tensor reader does not execute Python or arbitrary pickle callables. Training wrapper state dictionaries are not accepted; export a plain MemoryModule state dictionary as upstream does. Checkpoint tensor names and dimensions are checked strictly. Safetensors is preferred for deployment.

Encoder and decoder directories use Hugging Face `config.json`, `tokenizer.json`, and a single safetensors file or its shard index. Keep mapped files immutable while a handle is alive. Use the exact encoder and decoder pair used to train the memory checkpoint. Matching dimensions alone do not establish semantic compatibility. The text interface implements Qwen3 ChatML with thinking disabled and the original Memory placeholder delimiters. It supports greedy text generation, not tools, streaming, training or arbitrary model families.

The pretrained memory module has 194 million parameters. Its weights occupy roughly 388 MB in BF16 or 776 MB in F32, excluding overhead. The full text pipeline additionally loads the 4 billion parameter encoder and 8 billion parameter decoder. F32 model storage alone approaches 49 GB. Use a suitable GPU and a validated reduced precision configuration for that full deployment. The tiny committed pipeline fixture exercises mechanics without this allocation.

**Rust interface**

```rust
use latentmesh_memorilla::{Device, DType, MemoryModule, MemoryService};

fn main() -> latentmesh_memorilla::Result<()> {
    let checkpoint = std::path::Path::new(env!("CARGO_MANIFEST_DIR")).join("fixtures/learned");
    let module = MemoryModule::load(checkpoint, &Device::Cpu, DType::F32)?;
    let mut memory = MemoryService::new(module, "example", 1_000_000)?;
    memory.write("history", &[0.1; 24])?;
    let tokens = memory.read("history", &[0.2; 8])?;
    assert_eq!(tokens.shape, [1, 3, 12]);
    Ok(())
}
```

Run the committed example from this workspace with `cargo run -p latentmesh-memorilla --example memory`.

MemoryModule exposes direct inference with padding masks, learned or retrieval initialized slots, optional document self attention, cache writes, and shared collection cache reads. The service uses caching and therefore accepts the released learned slot architecture with no document self attention. No retraining is necessary to load the released weights.

**Evidence and limits**

The committed fixtures compare native computation with the original PyTorch memory implementation and Transformers Qwen3. They cover masked documents, retrieval initialization, document self attention, cached and direct memory, shared collections, Qwen3 input embeddings, KV continuation, complete text generation, input mutation after dispatch, namespace separation, resource limits and Node event loop progress. These fixtures use small randomly initialized models and do not measure task accuracy.

The released Stage 3 memory checkpoint was additionally checked against PyTorch using synthetic document and query embeddings. Direct, cached and shared reads passed a 0.0002 absolute error bound. See `validation/` for measured receipts. These measurements do not establish full pretrained encoder and decoder parity, task accuracy, production latency, fleet operation, radio delivery or CUDA performance. F16 and BF16 execution are available but require separate numerical qualification.

The repeated Apple M4 Pro benchmark recorded CPU median latency reductions of 56% to 77% across the five cases using Apple Accelerate and the algorithm changes. For eight queries over 1024 documents, Metal improved from 33.53 to 17.47 ms. Single query Metal results were mixed, including a 5% regression in one case. See [the benchmark report](validation/benchmark/README.md) for all 200 sample comparisons, source commits, binary hashes and limitations.

The default wire export uses F32 to preserve the returned Float32Array exactly. A released output is therefore 256 KiB of tensor bytes, plus JSON expansion and metadata. It is not a 16 token radio message. Do not send it through the current 32 fragment Meshtastic path; keep memory local and transmit compact results or references.

To regenerate the independent fixtures, use Python 3.11 or newer with PyTorch and Transformers 4.53.3 in an isolated development environment:

```sh
python reference/generate.py
python reference/qwen_fixture.py
python reference/generate.py --checkpoint /models/memorilla/stage3
MEMORILLA_CHECKPOINT=/models/memorilla/stage3 cargo test -p latentmesh-memorilla --test parity released_checkpoint_matches_pytorch -- --ignored --nocapture
node node/scripts/check-released.cjs /models/memorilla/stage3 core/fixtures/real/golden.json cpu validation/cpu.json
```

Acceptance test: `cargo test --locked -p latentmesh-memorilla` and `npm test` must pass, then the released checkpoint receipt must remain below the declared numerical tolerance. Production task quality requires an additional evaluation against RAG and shuffled memory using the deployment model pair.
