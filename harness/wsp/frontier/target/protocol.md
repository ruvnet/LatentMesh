# Prospective target domain calibration of the frozen readouts

The preceding experiment missed its registered comparison. This new test asks whether a receiver can lower the cost to native sentiment by calibrating on 600 target domain examples. Use the unchanged reference weights, feature basis, native class restriction and original thresholds from the preceding study. Apply the same rule to every transmitted arm and the no message alternatives. This measures an additional receiver provisioning cost of 600 sentiment labels, with no new weight payload. Score the old and new policy on the same newly reserved records.

For each method, raise its strictly greater than threshold to at least the largest score observed among calibration cases that the native sentiment model answers correctly and on which its native class restriction allows an override. Retain a disabled head or an empty eligible set as originally configured. This is a single prespecified alternative. No skill labels will be used to fit its thresholds. Freeze the calibration result before computing any evaluations.

Use the original pinned GoEmotions and TweetEval files. Recreate the 900 previous sentiment cases and exclude them. Remove duplicate normalized text, all GoEmotions texts and all TweetEval official emotion validation and test texts from the sentiment pool. Within each sentiment gold class, rank remaining IDs by SHA256 of the UTF8 string `latentmesh-target-v1/` plus the ID. Take the first 200 per class for calibration and the next 600 per class for evaluation. Publish exact ID hashes against the previous registered selection. The protected endpoint is the fraction of these 1,800 cases losing a correct native decision. Compute a 95% simultaneous upper bound by averaging the three class conditional one sided exact binomial upper bounds with tail 0.05/3. The target population is equally weighted across the three sentiment labels.

For independent skill tests, use up to 200 positive and 200 negative remaining examples from GoEmotions dev, excluding the preceding language trial's 64 shared dev anchors. Positives are anger and negatives are annoyance, disappointment, disgust and fear. The second test is the standard split/test from DAIR AI emotion (CARER), Hugging Face revision cab853a1dbdf4c42c2b3ef2173804746df8825fe, with up to 256 each from anger and sadness. Deduplicate CARER by normalized text, exclude all three GoEmotions splits and all available TweetEval emotion validation, emotion test and sentiment test texts. Use original file row numbers as CARER IDs. Sample equal available numbers in each binary stratum, with the same independent hash ranking. Freeze all fitted values before encoding or scoring either reserved skill population.

Report original versus target calibrated WSP on all endpoints and the strongest target calibrated compact comparator, paired label stratified bootstrap contrast with 20,000 replicates and seed 72191. For a superiority claim require a point advantage of at least two points and a simultaneous one sided bootstrap lower bound above two against every compact method on each skill population, using tail 0.05 / (2 times the number of controls). Require observed sentiment loss at most one point and its simultaneous class conditional upper bound below one point. Use one reference CPU and distinguish this result from the independently repeated original experiment and the official TweetEval leaderboard. Do not alter the original registered decision.
